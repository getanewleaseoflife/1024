# 岗位胜任力评估智能体 — 界面与视觉设计

> 版本：v0.2（设计规范 + 可视原型）
> 日期：2026-08-22
> 配套文档：`docs/PRD.md`（需求）、`docs/TECH_DESIGN.md`（技术方案）、`docs/ARCHITECTURE.md`（架构落地）
> 可视原型：`docs/design-prototype.html`（单文件自包含，浏览器直接打开，5 页可点击流转）
> 维护规范：本文为 UI/视觉**派生文档**，非权威；架构/技术栈/数据模型/边界变更仍须同步 `PRD.md` 与 `TECH_DESIGN.md`。

## 1. 设计目标与原则

对齐 PRD「拟人度 20 分」与「专业 / 沉稳 / 对话感」的定位，同时覆盖技术实现 20 分的记忆可视化演示点。

**五条设计原则：**

1. **专业优先**：整体观感像「资深 HR / 业务专家的评估工具」，而非玩具。深蓝主色、克制的装饰、无重阴影。
2. **对话即产品**：面试对话页是体验核心，追问、引用原话、肢体语言、打字机流式渲染都要让面试「有温度、有压迫感层次」。
3. **记忆可被看见**：L3 证据侧栏实时累积（维度 + 掌握度 + 引用原话），让评委直接「看见」长文本记忆在发生——这是技术分演示点，也是视觉重心。
4. **证据可信**：报告页每个分数都绑定候选人原话，引用用「证据标签」高亮呈现，强化「客观、可审计」的信任感。
5. **克制一致**：单一 icon 家族、4/8 间距节奏、语义 token 驱动，全站无一处「手写颜色 / 随机间距」。

**风格落点**（ui-ux-pro-max 检索结论）：Flat Design + Minimalism & Swiss Style，Product Type = Job Board/Recruitment（HR Analytics Dashboard 子类）。少量 AI 渐变仅用于品牌标识与人格标识，正文零阴影、零渐变。

## 2. 设计 Token

### 2.1 配色（语义化）

| Token | 值 | 用途 |
|-------|-----|------|
| `--color-primary` | `#0369A1` | 主色：主按钮、链接、当前步骤、雷达图 |
| `--color-primary-hover` | `#075985` | 主色 hover |
| `--color-secondary` | `#0EA5E9` | AI 点缀 / 亮蓝强调 |
| `--color-accent` | `#16A34A` | 成功绿 / 「已具备」/ 主 CTA |
| `--color-background` | `#F0F9FF` | 页面底（微蓝白） |
| `--color-surface` | `#FFFFFF` | 卡片 / 面板 |
| `--color-foreground` | `#0C4A6E` | 主文本 |
| `--color-muted` | `#E7EFF5` | 弱底 / 分隔底 |
| `--color-muted-foreground` | `#475569` | 次要文本 |
| `--color-border` | `#BAE6FD` | 边框 / 分隔线 |
| `--color-destructive` | `#DC2626` | 危险 / 错误 / 「缺失」 |

**语义扩展（Gap 三类 + 掌握度）：**

| 语义 | 主色 | 浅底 | 用途 |
|------|------|------|------|
| 成功 / 已具备 | `#16A34A` | `#DCFCE7` | Gap「已具备」标签 |
| 警告 / 待考察 | `#D97706` | `#FEF3C7` | Gap「待考察」标签 |
| 危险 / 缺失 | `#DC2626` | `#FEE2E2` | Gap「缺失」标签 |
| 中性 / 未考察 | `#64748B` | `#F1F5F9` | 雷达图「待考察」占位 |

**3 档人格标识色：**

| 人格 | 标识色 | 观感 |
|------|--------|------|
| 随和型（同级工程师） | `#0D9488` 翠绿 | 轻松、鼓励 |
| 严谨型（资深专家，默认） | `#0369A1` 深蓝 | 犀利、专业 |
| 压力型（HR 主管/经理） | `#BE123C` 绛红 | 压迫、质疑 |

> 对比度：正文 `#0C4A6E` on `#FFFFFF` ≈ 7.9:1；`#475569` on `#FFFFFF` ≈ 7.6:1；`#0369A1` on `#F0F9FF` ≈ 5.9:1，均 ≥ 4.5:1。深色模式 token 预留（见 §8），P0 仅实现浅色。

### 2.2 字体

- **西文/数字标题**：`Poppins`（600/700），营造现代专业感。
- **正文 / 中文**：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", "Source Han Sans SC", sans-serif`（Windows 11 下回退到微软雅黑）。
- 字号阶梯：`12 / 14 / 16 / 18 / 20 / 24 / 32`；正文 16px、行高 1.6；对话正文 15px、行高 1.7。
- 数字用 `tabular-nums`，防止评分 / 匹配度数字抖动。

Google Fonts（仅西文，中文走系统回退）：

```
https://fonts.googleapis.com/css2?family=Open+Sans:wght@300;400;500;600;700&family=Poppins:wght@500;600;700&display=swap
```

### 2.3 间距（4/8 系统）

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。页面 section 间距 32~48；卡片内 padding 20~24；对话气泡间距 16；证据条目间距 12。

### 2.4 圆角与阴影

- 圆角：`6px`（标签 / 小按钮）、`8px`（输入框 / 按钮）、`12px`（卡片 / 气泡）、`full`（pill / 头像）。
- 阴影（Flat 风格，极浅）：卡片 `0 1px 2px rgba(12,74,110,0.06)` + `1px` 边框；浮层/侧栏 `0 4px 16px rgba(12,74,110,0.10)`。正文卡片**用边框而非阴影**区分层级。

## 3. 页面结构与导航流转

用户旅程（PRD §3.3）：`进入系统 → 选岗位 → 投递简历 → 查看画像 → 选人格 → 面试 → 查看报告`。

5 页 + 顶部 5 节点 Stepper：

```
[岗位选择] → [简历输入] → [能力画像] → [模拟面试] → [评估报告]
```

- 顶部为 sticky 品牌栏（logo + 产品名），其下为 5 节点步骤条；当前节点高亮、已完成节点打勾、可回退点击。
- 面试与报告页为「沉浸式」，收窄顶部、弱化步进条存在感，让对话 / 报告成为焦点。

| 页 | 核心内容 | 关键视觉 |
|----|---------|---------|
| 岗位选择 | 3 岗位卡片（AI 算法[当前] / Java / 产品） | 卡片 + 维度标签 + 状态徽标 |
| 简历输入 | 粘贴文本域 + PDF 上传（增强项）+ 隐私说明 | 大文本域 + 解析 CTA + 加载态 |
| 能力画像 | 候选人基础信息 + Gap 三类分析 + 人格选择 | Gap 标签墙 + 3 档人格选择器 |
| 面试对话 | 对话流 + L3 证据侧栏 + 输入区 | 气泡 + 打字机 + 证据侧栏（重点） |
| 评估报告 | 雷达图 + 分维度得分 + 优劣 + 建议 + STAR | 雷达图 + 证据绑定（重点） |

## 4. 面试对话页（重点）

三栏布局：`[对话主区 2/3] [L3 证据侧栏 1/3]`，底部固定输入条。

### 4.1 对话流 + SSE 打字机

- 面试官气泡居左（白底 + 边框），候选人气泡居右（主色浅底）。
- SSE 流式渲染：最后一个 AI 气泡尾部显示**闪烁光标**（`▍` 动画，`prefers-reduced-motion` 下改为静态）。
- 气泡内追问引用候选人原话时，用「引用高亮」：浅蓝底 + 左侧竖线 + 斜体，提示「这是你的原话，正被追问」。
- 加载态：等待 AI 追问时显示「正在思考…」三点动效，不用阻塞全屏 spinner。

### 4.2 肢体语言 / 拟人化渲染

肢体语言描写 `(合上简历，叹气)` `(皱眉，身体前倾)` 单独成行，渲染为 **muted 斜体 + 小字号**，置于该 AI 气泡首行，与正文区分：

> `(合上简历，身体前倾)` —— muted 斜体
> 你刚才说「我们用了 Dropout 缓解过拟合」…… —— 正文，引用处高亮

### 4.3 L3 证据侧栏（记忆可视化演示点）

- 标题「能力证据 · 实时累积」+ 副标题「已覆盖 5/6 维度」。
- 每条证据 = 维度名 + 掌握度刻度（5 段）+ 引用原话（截断，hover 展开）。
- 新证据追加时：入场动画 `translate-y + fade`，符合 `stagger-sequence`（每条 30–50ms 错开）。
- 空态：「面试开始后，能力证据会在此实时累积」。

### 4.4 3 档人格视觉差异

| 人格 | 头像/徽标色 | 语气 | 追问密度 |
|------|-----------|------|---------|
| 随和型 | 翠绿 | 鼓励、慢 | 低 |
| 严谨型（默认） | 深蓝 | 犀利、专业 | 中 |
| 压力型 | 绛红 | 压迫、质疑 | 高 |

人格切换后：面试官头像边框、气泡边框、追问引用高亮色随之切换（token 驱动），让评委一眼看出「人格确实在变」。

## 5. 报告页（重点）

自上而下：

1. **综合匹配度**：大数字（如 `78%`）+ 等级徽标（「匹配」「待提升」等）+ 分维度小计。
2. **能力雷达图**：ECharts，岗位专属 6 维，单数据集 `#0369A1` 20% 填充 + 顶点数值标签；无证据维度以「待考察」占位（不连线）。
3. **分维度得分卡**：每个维度 = 分数 + 星级/刻度 + 绑定证据 quote。
4. **优势 / 劣势**：左右两卡，各列 2~3 条，每条挂证据。
5. **岗位匹配度 + 提升建议**：建议必须具体可执行（「补 Transformer 注意力机制推导」而非「多学习」）。
6. **STAR 分析**：项目经历按 情境/任务/行动/结果 四列。
7. **通用软素质**：沟通表达 / 逻辑思维 / 临场应变 三张 mini 卡。

**证据绑定（机械校验可视化）**：每个分数旁附「证据标签」`「原话」`，只允许引用、禁止编造；无证据维度不出分、雷达图标「待考察」。这是「报告客观性」的可信度来源。

雷达图无障碍兜底：图表下方附一张 `维度 → 得分` 数据表，`role="table"`，供读屏器 + 键盘；不依赖颜色区分维度。

## 6. 组件规范

| 组件 | 规格 |
|------|------|
| 对话气泡 | 面试官白底 + `border`；候选人 `primary` 浅底；圆角 12px，一侧小尖角；最大宽 78% |
| 证据标签（quote chip） | 浅蓝底 + 左侧 3px 竖线 + 斜体；hover 展开全文 |
| Gap 标签 | pill 型，主色字 + 浅底（绿/琥珀/红三态） |
| 评分卡 | 维度名 + 大号分数 + 5 段刻度 + 证据标签 |
| 人格选择器 | 3 卡横排，选中态描边 + 浅底 + 勾选角标；含头像 + 人格名 + 语气描述 |
| 主按钮 | `primary` 底、白字、`disabled` 用 0.38 透明度 + `cursor-not-allowed` |
| 次按钮 | 白底 + 边框 + `foreground` 字 |
| 输入框 | 高 ≥44px，可见 label（非 placeholder-only），错误在字段下方 + `aria-describedby` |
| Stepper | 5 节点 + 连接线，完成打勾、当前高亮、未来 muted |
| 图标 | Phosphor `@phosphor-icons/react`（备选 Heroicons）；线性风格、24px、stroke 1.5，统一 |

**交互统一**：所有可点击元素 `cursor-pointer`；hover 150–200ms 颜色/透明度过渡；`prefers-reduced-motion` 下禁用入场动效与打字机闪烁。

## 7. 交互与拟人化呈现小结

- 追问引用原话 → 「引用高亮」+ 证据标签（§4.1 / §6）。
- 肢体语言描写 → muted 斜体首行（§4.2）。
- 智能衔接语（"嗯，我理解了…"）→ 正常正文。
- 反问环节（"你有什么想问我的吗"）→ 面试官气泡 + 输入区切换为「向面试官提问」轻状态。
- 边界探测「降级提问」→ AI 气泡加「降级」小徽标，暗示题目在逐层下探。

## 8. i18n 与布局弹性（预留）

- 文案全部资源化（`zh-CN` 默认，`i18n` 架构预留），组件不硬编码字符串。
- 中英文长度差异：按钮/标签预留 `+30%` 宽度弹性，避免 `text-ellipsis` 截断语义；长 token/URL 用 `overflow-wrap: anywhere`。
- 深色模式：语义 token 已按 §2.1 分层，P0 仅实现浅色；切深色时用去饱和变体而非反色，独立测对比度。
- 响应式：移动端（<768px）证据侧栏折叠为抽屉，雷达图纵向布局、减少刻度。
