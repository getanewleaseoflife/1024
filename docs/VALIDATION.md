> 版本：v0.1
> 日期：2026-08-22
> 配套文档：`docs/PRD.md`（需求/验收）、`docs/TECH_DESIGN.md`（技术方案）、`docs/ARCHITECTURE.md`（架构落地）

## 1. 文档定位

本文集中定义「如何验证项目是否达标」，分四层：

| 层 | 定位 | 内容 |
|----|------|------|
| ① 评审标准（北极星） | 答辩评委打分目标，所有验证倒推来源 | 面试逻辑深度 30 / 报告质量 30 / 拟人度 20 / 技术实现 20 |
| ② 交付清单 | 最终对照打勾 | PRD §6 分模块验收 checklist |
| ③ 技术硬指标 | 客观可复现门槛 | 金标 / 注入 / 性能 |
| ④ 切片判据（过程门禁） | 每切片「过没过」 | S0~S5 可验证产出 |

---

## 2. 金标测试集（追问分类）

**目标**：验证追问分类器质量（对应「面试逻辑深度 30 分」）。

**构造**：手写 40~60 条「典型回答 → 期望 action」，覆盖 7 动作 × 6 维度 + 边界样本（答非所问 / 注入诱导 / 超短·超长回答 / 追问上限前最后一答）。

**评判口径与阈值**：

| 指标 | 达标线 | 说明 |
|------|--------|------|
| action 精确一致率 | ≥ 85% | 与金标 action 完全一致 |
| 同类别容错一致率 | ≥ 95% | 追问类（澄清/验证/深挖/挑战/迁移）内互错、状态类（换题/收尾）内互错算容忍 |
| 跨界错判 | 0 容忍 | 该追问却换题/收尾、该收尾却追问 → 状态机硬护栏兜底 |
| `evidence.quote` 子串校验 | 100% | quote 必须是回答原话子串（防编造证据，机械规则） |

---

## 3. 注入测试集（防注入）

**目标**：验证 Prompt 注入防护链路（`<candidate_answer>` 包裹 + 系统层不可覆盖 + 证据化评分天花板）。

**构造**：手写 20~30 条，四类——① 身份劫持；② 提分诱导；③ 规则覆盖；④ 提示词泄露。

**「越权结果」定义（= 拦截失败）**：报告分被抬高（偏离无注入基线 > 1 档）或无证据维度凭空出分；面试官执行诱导指令；面试官泄露系统提示 / 切换身份。

**阈值**：

| 层 | 达标线 |
|----|--------|
| 评分/报告层 | 100%（0 容忍） |
| 追问层 | ≥ 95% |

**度量方式**：同一回答跑「有注入 vs 无注入」两份，比报告分差异 + 判读追问是否越权。

## 4. 切片级判据（过程门禁）

> 门禁规则：某切片可验证产出不达标 → 不进下一片，先修本片。

| 切片 | 通过判据（可验证产出） |
|------|----------------------|
| S0 冒烟 | 前端一句话 → 后端 → DeepSeek → SSE 流式回显 |
| S1 简历解析 | 简历 → 教育/技能/项目/经历（准确率 ≥80%）→ 画像 + Gap 可见 |
| S2 单题问答 | 分类器出 `{action, evidence}` → L3 落库 → 流式追问一次；L3 侧栏可见；金标子集（10~20 条）预验 |
| S3 完整面试 | 状态机跑完「开场 → 核心 6~8 题 → 收尾」；≥3 种 action；3 档人格可辨；降级提问可用；金标全量 40~60 条达标 |
| S4 报告 | 雷达图 + 优劣 + 匹配度 + 建议 + STAR；证据绑定机械校验生效；注入全量 20~30 条达标 |
| S5 打磨 | 拟人化到位；虚拟人跟读（说话状态与音频同步、播报失败静默退回文字）；边界稳健；快速演示模式 3 题跑通；性能达标 |

> S0~S5 覆盖 P0 核心闭环；M5 岗位扩展 / M6 增强项为后续切片，届时另定判据。

## 5. 性能指标（硬软分界）

| 指标 | 目标 | 性质 | 测量 |
|------|------|------|------|
| RAG 检索 | < 500ms | **硬**（纯本地 Chroma+BGE，可复现） | 本地基准脚本，取 p95 |
| 追问首 token | < 2~3s | 软（吃 DeepSeek 网络） | 现场实测留档 |
| 报告生成 | < 10s | 软（含 LLM 调用） | 现场实测留档 |

> 软目标超标不阻塞交付，用降级链（重试 → 缓存回放 → Mock）保证不断流。
